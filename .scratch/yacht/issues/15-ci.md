# 15: CI (코드를 올릴 때마다 자동 검사)

**What to build:** GitHub에 코드를 올릴 때마다 단위 테스트, 타입 검사, Biome 검사, 문서 검사(용어·티켓 관계)가 자동으로 돌고, 실패하면 알 수 있다. 같은 검사가 커밋 전에도 돈다.

**Blocked by:** 01

**Status:** ready-for-agent

> GitHub 원격(`CaesiumY/party-games`, 공개)은 이미 연결되어 있다. 이슈 관리를 GitHub Issues로 옮길지는 `/setup-matt-pocock-skills` 를 다시 돌려 따로 정한다.

- [ ] 푸시와 PR마다 단위 테스트, 타입 검사, Biome 검사, 문서 검사가 돈다.
- [ ] 용어 검사: `GLOSSARY.md` 의 `_Avoid_` 목록을 읽어, 스펙·티켓·ADR에서 그 단어가 쓰인 곳을 실패로 보고한다. 같은 글자라도 뜻이 다른 쓰임(예: 홀드 자리의 "다섯 칸", 윗칸·아랫칸)은 허용 목록으로 뺀다.
- [ ] 티켓 관계 검사: 각 티켓의 선행 티켓 번호가 자기 번호보다 작은지, 티켓 본문의 "NN의 …" 참조가 실제 선행 티켓(또는 그 선행)을 가리키는지 확인한다.
- [ ] 커밋 전 검사(pre-commit 훅)로 Biome 검사와 문서 검사를 돌린다. 훅 도구를 새로 들일 때는 도입 전에 사용자 승인을 받는다.
- [ ] pnpm 의존성 캐시를 써서 반복 실행이 빠르다.
- [ ] E2E는 이 티켓에서 붙이지 않는다. 11이 이 CI 위에 E2E를 추가한다.
