# 11: CI (코드를 올릴 때마다 자동 검사)

**What to build:** 스펙의 CI 절에 적힌 자동 검사가 GitHub에 코드를 올릴 때와 커밋 직전에 돌아서, 실패하면 바로 알 수 있다. 이 티켓에서 처음 생기는 것은 문서 검사 두 가지(용어 검사, 티켓 관계 검사)다.

**Blocked by:** 01

**Status:** ready-for-agent

- [ ] 스펙 CI 절의 검사 목록이 푸시·PR 때와 커밋 직전 검사(pre-commit 훅)에서 각각 그대로 돈다. 훅 도구를 새로 들일 때는 도입 전에 사용자 승인을 받는다.
- [ ] pnpm 의존성 캐시를 써서 반복 실행이 빠르다.
- [ ] 용어 검사: 용어집의 각 용어에 붙은 "피할 말"이 스펙·티켓·ADR에 쓰인 곳을 실패로 보고한다.
  - 피할 말이 그 자체로 용어집의 표제어이기도 하면(예: "기록") 검사하지 않는다.
  - 맞춰 보는 단위는 어절이다. 한 글자짜리 피할 말(예: "통")은 그 말만으로 된 어절일 때만 걸린다("통과"는 걸리지 않음).
  - 같은 글자라도 뜻이 다른 쓰임은 (피할 말, 구절) 짝의 허용 목록으로 뺀다. 허용 목록은 첫 실행 결과를 하나씩 보고 만들며, 실제 오용이면 허용 목록에 넣지 않고 문서를 고친다. 예상되는 예: 다섯 칸, 조작 잠금, 고정 카메라, 저장 항목, 물리 시뮬레이션, 온라인 멀티플레이, 이름 입력, 정렬 순서.
  - 완료 시점에 지금 문서들로 돌린 결과가 실패 0건이다.
- [ ] 티켓 관계 검사: 각 티켓의 선행 티켓 번호가 자기 번호보다 작은지, 본문의 "NN의 …" 참조가 선행 티켓을 거슬러 올라가 닿는 어느 티켓인지 확인한다. NN은 앞뒤에 다른 숫자가 붙지 않은 두 자리 수만 센다("11234의"는 참조가 아님).
- [ ] E2E는 이 티켓에서 붙이지 않는다. 12가 이 CI 위에 E2E를 추가한다.
