# 01: 프로젝트 골격과 첫 굴림 → 초이스 기록

**What to build:** 브라우저에서 앱을 열면 3D 판 위에 주사위 5개(물리 없는 단순 정육면체, 위를 향한 면에 눈 표시)가 보인다. 굴림 버튼을 누르면 다섯 눈이 바뀌고, 초이스 카테고리에 다섯 눈의 합을 기록할 수 있다. 휴대폰 세로 화면에서도 판·점수표·버튼이 한 화면에 들어오고, 3D를 쓸 수 없는 기기에서는 안내가 보인다.

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] pnpm·Vite·TypeScript·React·react-three-fiber·zustand·Biome·Vitest가 세팅되어 개발 서버, 테스트, Biome 검사, 타입 검사가 각각 한 명령으로 돈다. 각 라이브러리는 최신 안정판을 확인해 버전을 고정한다.
- [ ] 게임 엔진은 React·three.js·브라우저 API에 의존하지 않는 순수 모듈이다. 게임 상태는 직렬화 가능한 단순 데이터다(직렬화 → 복원 → 같은 상태임을 테스트로 확인).
- [ ] 게임 엔진은 주사위 공급원을 바깥에서 주입받는다. 공급원은 (플레이어, 턴, 굴림 번호, 굴릴 주사위 개수)를 받는다. 운영 공급원은 암호학적으로 안전한 난수를 쓴다. 테스트는 정해진 눈을 내는 공급원으로 초이스 기록 점수를 검증한다(TDD).
- [ ] 주사위 다섯 개는 턴 안에서 정체성이 유지된다.
- [ ] 규칙에 맞지 않는 명령의 거부 방식(무시 또는 오류 반환)을 하나로 정하고, 첫 굴림 전 기록 거부를 테스트한다.
- [ ] 굴림 연출 입구가 있다: 굴림 결과와 홀드 상태를 받아 **멈춤**과 **정렬 끝** 두 시점을 알린다. 첫 구현은 순간 배치이며, 이것이 '동작 줄이기' 경로가 된다. 굴림 결과는 굴림 명령 시점에 정해진다(ADR-0001).
- [ ] 기기의 '동작 줄이기' 설정을 감지해 저장소에 둔다. 이 설정이 켜져 있으면 이후 어떤 연출 구현이 들어와도 순간 배치 경로를 쓴다.
- [ ] 상태 저장소가 연출 진행 중 여부를 들고, 굴림·홀드·기록 가능 여부를 한 곳에서 판정한다. 굴림 버튼을 누른 때부터 정렬 끝까지는 엔진에 명령을 보내지 않고 카테고리 선택도 막는다. 굴림 버튼을 누르면 선택은 지워진다.
- [ ] 고정 카메라가 판을 비스듬히 내려다본다. 사용자가 시점을 돌릴 수 없다.
- [ ] 모바일 세로 화면이 3D 판·점수표·버튼 영역으로 나뉘는 틀이 있다(375×667에서 스크롤 없음).
- [ ] WebGL을 쓸 수 없으면 "이 기기에서는 3D를 지원하지 않는다" 안내만 보인다.
